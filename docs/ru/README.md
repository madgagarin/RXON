# Протокол RXON (Reverse Axon)

**RXON** (Reverse Axon) — легковесный протокол обратного подключения, распределения задач и типизированного межсервисного взаимодействия в архитектурах **[HLN (Holarchical Logic Network)](https://github.com/madgagarin/hln)**.

Протокол предоставляет строго типизированные модели сообщений и механизм проверки подлинности данных (Zero Trust) для распределенных агентных сред.

## Концепция

В классических клиент-серверных сетях управляющий узел отправляет запросы на воркеры напрямую (Push). В **RXON** подчиненный узел (shell / воркер) сам инициирует исходящее соединение к оркестратору и забирает задачи (Pull). Это позволяет воркерам работать за NAT и межсетевыми экранами без проброса входящих портов, сохраняя постоянный двусторонний канал управления.

## Возможности

- **Обратное подключение (модель Pull)**: воркеры подключаются к оркестратору по исходящему каналу, что упрощает запуск за NAT и файрволами.
- **Верификация данных Zero Trust**: подпись сообщений через HMAC-SHA256 (симметричная) и Ed25519 (асимметричная), сравнение подписей за константное время, цепочки вызовов (`bubbling_chain`) и цифровая подпись задач оркестратором (`sig`).
- **Контекст политик и телеметрии**: поддержка ограничений выполнения (`policy`), глубины вызовов в холархии (`depth`), номера шага в пайплайне (`step`), хеша родительского события (`parent_hash`), отчета о затратах (`costs`), уровней риска навыков (`risk`) и требуемых прав (`permissions`).
- **Квитанции выполнения (`ExecutionReceipt`)**: структура для логирования маршрутизации, перебора кандидатов, срабатывания fallback и времени принятия решений.
- **Вывод и валидация схем**: генерация JSON-схем из сигнатур Python-обработчиков (`msgspec.Struct`, `dataclass`, duck-typed модели с `model_json_schema`, примитивы). Скомпилированные валидаторы кэшируются в потокобезопасном LRU-кэше с ограничением размера (до 2048 записей).
- **Детерминированная сериализация**: утилита `to_dict` нормализует вещественные числа (`1.0` -> `1`), удаляет поля со значением `None` и сортирует ключи через `orjson` для получения стабильного криптографического хеша.
- **Преобразование моделей**: утилита `from_dict` на базе `msgspec` для рекурсивного восстановления типизированных объектов (`Struct`, `dataclass`, `Enum`, `UUID`, `datetime`).
- **Сопоставление ресурсов**: подбор воркеров под требования задач по правилам «больше или равно» (для числовых параметров) и проверки вхождения/пересечения множеств.
- **Устойчивый транспорт**: клиенты WebSocket и HTTP-поллинга с обновлением токенов, экспоненциальным backoff и обработкой HTTP 429 (`Retry-After`).

## Экосистема

RXON используется как базовый протокол взаимодействия в проектах:

- **[HLN (Holarchical Logic Network)](https://github.com/madgagarin/hln)**: спецификация и архитектурный манифест самоподобных холархий.
- **[Shellspirit](https://github.com/madgagarin/shellspirit)**: распределенный оркестратор длительных AI-процессов на базе конечных автоматов.
- **[Shellnode](https://github.com/madgagarin/shellnode)**: SDK для написания автономных воркеров (холонов), подключающихся к оркестратору по RXON.

## Архитектура и логика

### Целостность и валидация данных

1. **Стабильность сериализации**: через `orjson` формируется канонический JSON — целые числа в `float` приводятся к целочисленному представлению (`10.0` -> `10`), строковые ключи сортируются, ключи словарей приводятся к строкам. Это исключает расхождение HMAC-хешей из-за форматирования.
2. **Поддержка типов**: прямая поддержка `msgspec.Struct`, стандартных `dataclass`, `datetime`, `UUID`, `Enum`, а также сторонних моделей с методами `model_json_schema()` или `schema()`.
3. **Ограничение глубины рекурсии**: обход структур ограничен глубиной 30 уровней для защиты от переполнения стека на циклических или чрезмерно вложенных объектах.
4. **Проверка по схемам**: схемы компилируются и сохраняются в памяти. Перед запуском задачи параметры могут проверяться на соответствие входной схеме навыка с ранним отклонением некорректных типов или отсутствующих обязательных полей.

### Сопоставление ресурсов

RXON формализует правила назначения задач на подходящие узлы:

1. **Аппаратные устройства**: проверка параметров `HardwareDevice`. Для числовых характеристик применяется правило «не меньше требуемого» (например, `vram_gb: 16` сопоставится с `vram_gb >= 16`).
2. **Общие свойства**: скалярные поля в словаре `properties` сравниваются по той же числовой логике.
3. **Списки возможностей**: если задача допускает список значений (например, `["linux", "darwin"]`), проверяется вхождение значения воркера либо непустое пересечение множеств.

### Контекст исполнения и политики

- **Ограничения (`policy`)**: словарь с параметрами выполнения (разрешенные навыки, бюджет токенов, лимиты времени).
- **Иерархия вызовов (`depth`, `step`, `parent_hash`)**: отслеживание уровня вложенности (`depth`), шага перехода (`step`) и хеша родительского события (`parent_hash`).
- **Подпись задачи (`sig`)**: подпись HMAC-SHA256, сформированная оркестратором с ключом `ORCHESTRATOR_SECRET_KEY` и проверяемая воркером перед стартом.
- **Временная метка (`timestamp`)**: целочисленный Unix-timestamp в секундах (`int`) для исключения погрешностей чисел с плавающей точкой.
- **Учет затрат (`costs`)**: поле `TaskResult.costs` для передачи фактически израсходованных ресурсов (токены, вычислительное время, стоимость).

## Стандартные коды ошибок

- `CONTRACT_VIOLATION_ERROR`: полезная нагрузка не соответствует ожидаемой схеме.
- `SECURITY_ERROR`: сбой аутентификации, истечение срока токена или несовпадение подписи.
- `RESOURCE_EXHAUSTED_ERROR`: недостаточно памяти, видеопамяти или вычислительных ресурсов.
- `DEPENDENCY_ERROR`: недоступен зависимый сервис, воркер или артефакт.

## Быстрый старт

### Сторона воркера (Pull)

```python
from rxon import create_transport
from rxon.models import HardwareDevice, Resources

# 1. Инициализация транспорта (поддерживает http, https, ws, wss)
transport = create_transport("ws://api.hln.local", "worker-01", "secret-token")

# 2. Описание доступных ресурсов воркера
my_res = Resources(
    properties={"ram_gb": 64, "cpu_cores": 16},
    devices=[HardwareDevice(type="gpu", model="RTX 4090", properties={"vram_gb": 24})],
)

# 3. Проверка соответствия требованиям (например, GPU от 16GB VRAM)
req = Resources(devices=[HardwareDevice(type="gpu", properties={"vram_gb": 16})])
if my_res.matches(req):
    print("Воркер подходит для выполнения задачи")
```

### Сторона оркестратора (сервер)

```python
from aiohttp import web
from rxon import HttpListener

app = web.Application()
listener = HttpListener(app)

# Регистрация маршрутов RXON до запуска приложения
listener.setup_routes()


async def my_handler(action, payload, context):
    if action == "poll":
        return {"job_id": "j-1", "task_id": "t-1", "type": "echo"}
    return {"status": "ok"}


await listener.start(handler=my_handler)
```
